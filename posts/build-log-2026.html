建站日志：这个博客是怎么长出来的

2026-10-26 约 6 分钟 1700 字 拾光

从 10 月 24 日第一次提交到今天，这个站的 git 历史里躺了四十多次提交、三十多个版本标签。这篇文章把整个过程摊开——包括两次大型翻车和救命的回滚。

第一阶段：骨架（v0.1 - v0.7）

第一天的目标很朴素：让一个纯静态站"像个博客"。设计系统、站点脚本、文章数据结构先落地，然后首页打字机、博客列表筛选搜索、文章模板、归档时间线、关于页、404 页逐页长出来。因为是零依赖纯静态，每一页就是一份 HTML，没有构建步骤，打开即用。

骨架期最重要的一次提交其实是部署：接上 GitHub Actions 之后，git push 一分钟后网站自动更新——这让后面所有疯狂迭代都没有后顾之忧。

第二阶段：壁纸的十七轮战争（v1.4 - v1.5）

站能跑了，我开始折腾"氛围"。主题背景系统从程序绘制的极光，换到 AI 生成的壁纸，再换到真实摄影作品，中间经历了至少七轮"去雾、增艳、锐化、重生成"的拉锯——git log 里 v1.4.3 到 v1.4.9 全是壁纸调色的痕迹。

最惨烈的一次是 v1.5.3：换上 NASA 彩色摄影的当天就整体回滚到 v1.4.7。教训很具体：先小步验证，再全量替换。那次之后我养成了每个阶段性改动都打标签的习惯——回滚时一句 git checkout v1.4.7 就能回到任意历史节点。

第三阶段：让它有点"活"气（v1.6 - v1.8）

静态站看久了会腻，于是有了：个人主页（在线编辑资料，本地保存）、首页星系（NASA 实拍旋涡星系抠图 + 双环轨道 + 光环粒子）、相册空间和音乐空间（IndexedDB 大容量存照片、多平台音乐播放器）。这些功能全部零后端——数据要么在仓库里，要么在访客自己的浏览器里。

零依赖不是妥协，是选择：没有构建链就没有构建链的 bug，没有数据库就没有数据库的运维。

第四阶段：工程化收尾（v1.9）

最后补上"看不见但重要"的东西：og 分享卡片、feed.xml 和 sitemap.xml 改为 GitHub Action 自动生成（发文章再也不用手动同步 RSS）、全部壁纸转 webp（流量省 45%）、Service Worker 离线阅读。至此，写文章的完整流程变成：复制模板 → 写正文 → 在 posts.js 加一条元数据 → push，其余全自动。

数据说话

三周时间的产出：10 个页面、7 篇文章、10 套动态壁纸主题、2 个内容空间、40+ 次提交、32 个版本标签、2 次大型回滚、0 个运行时依赖。

如果你也想有一个完全属于自己的角落，我的建议就三条：用 git 管好版本（它是你唯一的时间机器）、每个阶段都打标签（回滚成本趋近于零）、先跑起来再优化（完美是迭代出来的，不是设计出来的）。
